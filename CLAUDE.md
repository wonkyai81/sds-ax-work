## Submission rules (fixed)

- Stack: Python, LangChain, LangGraph. Models come from Amazon Bedrock through `ChatBedrockConverse`. Create agents with `create_agent` from `langchain.agents`.
- Layout: `src/agent.py` (main agent graph), `src/tools.py` (domain tools), `src/api.py` (FastAPI app), `src/config.py` (reads `.env`; approved new file), `src/ui.py` (Streamlit verification UI, kept), `web/index.html` (HTML + JS + Tailwind UI served by `GET /`; shows progress through `POST /query/stream`, an NDJSON variant of `/query`), `data/` (mock per-item KRW cost samples only, not real external data; not created yet), `evaluation/` (`test_queries.csv` covering AC1–AC6, `run_eval.py` which scores the questions against the real model, and per-round reports and result files). `tests/` is added and approved by the user. `requirements.txt` and `.gitignore` also exist. `src/retriever.py` is not created because RAG is out of scope. Do not move or rename the listed files.
- API: `POST /query` reads `question` (one natural-language line) and optional `session_id` (omitted on the first request; the server returns one inside `answer`). It returns `answer`, `contexts`, and `trace`. `answer` is a JSON object with `session_id`, `plainAnswer` (text), and `html` (report HTML, empty when there is no report). Errors use `{"error": {"code", "message"}}` with HTTP 422, 404, or 500. The trip fields (destination, origin, days, people, budget, start date) are extracted from the sentence by the model (`extract_trip`, structured output); code only checks for blank values and fills them from the rule parser `parse_trip`, which also serves as the fallback when the model call fails. Non-trip requests (secrets, personal data, real-time lookup) and missing trip fields are rejected by a rule-based Guardrail in `src/tools.py` and `src/api.py` before the graph runs, as HTTP 422; see `doc/DESIGN.md` section 16. Required trip inputs are destination, trip length, and party size (people, adults only); budget is optional, and with no budget the plans are generated without a spending limit. The departure city is optional and defaults to Seoul (shown as the default); flights are searched origin to destination, and the report shows both the outbound and the return flight with dates and times. The report table has departure and arrival time columns next to the day column (HH:MM). If the user states travel dates (e.g. `12월 20일부터 23일까지`, `2026-12-20~2026-12-22`), MCP lookups use those dates; otherwise they use today + 30 days (D+30), and the input box says so. The plan-selection `plainAnswer` carries one block per plan under its `- name: total ...` line (indented lines: `예산 대비:` budget usage, `차별점:` a 2-3 sentence comparison with the other plans (max 250 characters) written by a `compare_plans` LLM step with a code fallback, and `주요 일정:` up to five code-picked highlights that favor attractions; a restaurant appears only if its Google rating is at least 4.5 with at least 5,000 reviews, at most one); the web UI renders them as cards. A 1-day trip has no lodging. Per-person items (tickets, flights, restaurant meals) carry a unit price and the code computes the total as `unit price x people`; the report shows it as `unit price x people = total`. `contexts` holds tool-call results. Session state (selected plan, chat history) lives in server memory.
- Code: one role per file. Write Korean docstrings for functions and tools. Read secrets from `.env` and never hardcode them.
- Do not create files the user has not asked for. Do not rewrite an existing file wholesale; change only the parts that need it.

## Commands

No build or lint tooling. Tests are pytest runs in `tests/` (`test_budget.py`, `test_plans.py`, `test_readjust.py`, `test_chat_edit.py`, `test_report.py`, `test_config.py`, `test_api.py`). They mock the model and external lookups and use no network.

- Run all tests: `python -m pytest tests -q`
- Run one test file: `python -m pytest tests/test_readjust.py -q`
- Run one test: `python -m pytest tests/test_readjust.py::<test_name> -q`
- Run the server (serves the web UI at `/`): `uvicorn src.api:app --port 8000`
- Score the evaluation questions against the real Bedrock model (needs `.env`): `python evaluation/run_eval.py [--ids TQ-01,TQ-06]`

Streamlit (`src/ui.py`) is used only for manual verification; it reads `TRAVEL_API_URL` (default `http://localhost:8000`).

## Architecture

- **Split of responsibilities:** the LangGraph agent in `src/agent.py` drives itinerary generation, the re-adjustment flow, plan comparison, the guide, and chat edits. Tools in `src/tools.py` do the deterministic work: totals, budget verdicts, attempt counting, headcount math, sorting, rendering, the guardrail rules, and the external lookup clients. The web UI (`web/index.html`) and Streamlit (verification only) collect input, show the plans, send chat messages, and show the report. They call `POST /query` (the web UI uses `/query/stream`) and hold no agent logic.
- **Flow:** validate → optional research nodes → 3 plans in parallel → budget check and re-adjustment → `compare_plans` → select (interrupt) → route lookup and guide in parallel → report → chat edit loop (interrupt). Before a plan is selected, edit requests are rejected with 422 `edit_before_selection`. The guide is generated once, right after selection. See `doc/detail_design.md`.
- **Budget decisions are code, not LLM:** the LLM returns per-item KRW estimates; tools sum them and decide each plan's verdict. Where a lookup supplies the value, code sets it instead of the LLM: a restaurant whose Google `price_level` is known gets a fixed per-person price (INEXPENSIVE 10,000 / MODERATE 20,000 / EXPENSIVE 50,000 / VERY_EXPENSIVE 100,000 KRW, `MEAL_PRICE_BY_LEVEL` in `src/tools.py`); flight and lodging amounts that MyRealTrip returned overwrite the LLM's values (`apply_price_quotes`: flights by the cheapest direct fare, or the cheapest overall for 가성비형; lodging only when the hotel name matches a queried one); the exchange-rate multiplication and headcount math are also code (`finalize_items`). Ticket and tour prices are still transcribed by the LLM. 맛집형 and 명소형 must be at or under the full budget; 가성비형 at or under 80% of it.
- **Re-adjustment rules:** each over-budget plan gets at most 3 automatic re-adjustment attempts, counted per plan. If none fits, show the attempt with the smallest overage, with a warning. A chat edit that pushes the selected plan over budget runs the same loop again.
- **Bedrock access:** `ChatBedrockConverse`. Region and model come from `AWS_DEFAULT_REGION` and `BEDROCK_MODEL_ID` in `.env`, never from code. The user never enters credentials. Tests mock the model and make no network calls.
- **State:** the selected plan and chat history live only while the browser tab stays open. There is no database, server-side file storage, or login. The browser can download the report as an HTML file ("HTML로 내보내기"). External data lookup is optional and off by default: it connects only when `MOCKDATA_USE=False` in `.env`, using Google Maps MCP (`GOOGLE_MAPS_API_KEY`), MyRealTrip MCP (`MYREALTRIP_MCP_URL`, no key), Naver Maps (`NAVER_*`, `X_NCP_APIGW_*`), Frankfurter, OpenWeatherMap, and Wikipedia images. A missing key or failed lookup skips that lookup and falls back to the LLM estimate; keys never appear in logs or error messages. RAG is excluded. Do not add a database, login, or booking integration without a new interview or updated SERVICE.md.
- **Currency:** all amounts and budget checks are in KRW, including for overseas destinations. When `MOCKDATA_USE=False`, the `get_exchange_rate` tool (Frankfurter, ECB rate, no key) gives the local-currency-to-KRW rate, and `get_weather_forecast` (OpenWeatherMap 5-day forecast, `OPENWEATHER_API_KEY`) gives the weather. Both are LangChain tools in `src/tools.py`, run by the `research_conditions` node, and fall back to the LLM estimate when a lookup fails or the key is missing. The rate is injected into the plan prompts only so the LLM converts local prices to KRW; budget checks still sum KRW amounts in code. The forecast covers 5 days, so it feeds the plan prompts only when the trip dates fall inside it; otherwise the report shows it as reference only.
