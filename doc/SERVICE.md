# 여행 일정 에이전트 웹앱 — SERVICE

> 인터뷰 세션 `interview_20261104_024537` 기준으로 정리한 서비스 정의서입니다.
> 실행용 Seed는 `seed_ec1db24038dc` 입니다 (현재 문서 기준으로 재생성). 이전 Seed `seed_ebc6e7d8804c` 는 대체되었습니다.

## 1. 목적

사용자가 **여행지, 여행 기간, 예산(원화)** 을 입력하면, AI 에이전트가 예산에 맞는 여행 일정 후보 3개를 만들어 주고, 사용자가 그중 하나를 고르고 대화로 고쳐 나가며, 최종적으로 선택한 일정의 **HTML 리포트** 를 화면에서 확인하는 웹앱입니다.

## 2. 범위

### 포함 (v1)
- 여행지·기간·예산 입력 (제한 없음: 기간, 예산, 국내·해외 모두 허용)
- 일정 후보 3안 생성 (맛집형, 명소형, 가성비형)
- 사용자 선택 (HITL: Human-in-the-loop)
- 선택한 안에 대한 대화형 수정
- 예산 초과 시 AI 자동 재조정
- 선택한 안의 HTML 리포트 화면 표시

### 제외 (v1)
- 외부 데이터 조회 (항공·숙박 가격, 장소 정보 API 등) — **v2로 이관**. MCP 연동으로 구현 예정. v1의 모든 비용은 LLM 지식으로 추정
- 로그인, 계정
- 일정·리포트 저장, 공유, 다운로드
- 새로고침 후 상태 복원 (선택한 안과 대화 이력은 같은 탭이 열려 있는 동안만 유지)
- 환율 설정·환율 API (해외 비용도 LLM이 원화로 직접 추정)
- RAG 파이프라인 (문서 검색, 임베딩, 벡터 저장소). 답변 근거는 도구 호출 결과로만 제공

## 3. 사용자 흐름

1. **입력**: 여행지, 기간, 예산(원)
2. **3안 생성**: 맛집형 / 명소형 / 가성비형 각각 일차·시간대별 일정과 항목별 비용(원) 제시
3. **예산 검사**: 코드가 합계를 계산하고 예산 충족 여부를 판정 (아래 4절)
4. **안 선택**: 사용자가 한 안을 고름
5. **대화 수정**: 예) "2일차 저녁을 고급 스시 오마카세로 바꿔줘"
   - 수정 후 합계가 예산을 넘으면 자동 재조정 실행
6. **리포트**: 선택한 안의 HTML 리포트를 화면에 표시

## 4. 예산 규칙

| 안 | 예산 기준 |
|---|---|
| 맛집형 | 합계 ≤ 사용자 예산 |
| 명소형 | 합계 ≤ 사용자 예산 |
| 가성비형 | 합계 ≤ 사용자 예산의 80% |

- **판정 주체**: 코드. LLM은 항목별 금액만 추정하고, 합계와 충족 여부는 코드가 계산합니다.
- **통화**: 모든 금액과 판정은 원화(KRW). 해외 여행지도 LLM이 원화로 바로 추정합니다.

### 자동 재조정
- 예산을 못 맞춘 안마다 **안별로 최대 3회** 재조정합니다.
- 3회 후에도 못 맞추면 **가장 근접한 안**을 보여줍니다. 가장 근접한 안은 "목표 예산 대비 초과 금액이 가장 작은 시도"입니다.
- 가장 근접한 안에는 초과 경고를 함께 표시합니다.
- 대화 수정으로 선택한 안의 합계가 예산을 넘으면 같은 재조정 규칙(최대 3회, 가장 근접한 안)을 다시 적용합니다.
- 3안 제시 기능(HITL 선택)과 예산 초과 재조정은 **서로 독립된 기능**입니다.

## 5. 리포트 구성

선택한 안의 HTML 리포트에 아래 항목이 포함되어야 합니다.

- 일차·시간대별 일정
- 항목별 활동, 비용(원), 교통수단, 비고 (비용 근거 또는 특이 사항)
- 항목별 비용 합계
- 예산 대비 잔액 (예산 − 합계, 초과 시 음수)
- 초과 경고 (합계가 목표 예산을 넘을 때)

표시 방식: **화면에 표시** (파일 다운로드 없음).

## 6. 기술 구성

| 구분 | 선택 |
|---|---|
| 백엔드 | FastAPI (Python) |
| 에이전트 | LangChain, LangGraph. Agent 생성은 `langchain.agents`의 `create_agent` 사용 |
| LLM | Amazon Bedrock, `ChatBedrockConverse` 로 호출 |
| UI | Streamlit (검증용) |

> 인터뷰 당시의 `boto3` 직접 호출은 위 규약에 따라 `ChatBedrockConverse`로 대체했습니다. 이전 Seed `seed_ebc6e7d8804c`의 해당 가정은 새 Seed `seed_ec1db24038dc` 에서 바뀌었습니다.

### 역할 분담
- **에이전트 (LangGraph, `src/agent.py`)**: 일정 생성, 재조정 흐름, 대화 수정 흐름을 그래프로 구성
- **도구 (`src/tools.py`)**: 합계 계산, 예산 판정, 재조정 시도 횟수 관리 등 결정적 로직. 판정은 LLM이 아니라 도구(코드)가 수행
- **API**: FastAPI, 제출 규약의 `POST /query` 하나만 외부에 노출 (아래 6.1)
- **Streamlit**: 입력, 안 선택, 대화 입력, 결과 표시만 담당. 에이전트 로직은 두지 않음. 검증용 UI이며 `POST /query`를 호출해 동작

### 6.1 API 계약 (제출 규약)
- 요청: `POST /query`, 본문 필드
  - `question`: 사용자의 **자연어 요청 한 줄**
  - `session_id`: 첫 요청에서는 생략. 서버가 새 세션을 만들어 응답에 돌려주고, 이후 요청에는 이 값을 함께 보냄
- 응답: `answer`, `contexts`, `trace` 세 키
  - `answer`: JSON 구조. 아래 두 키를 가짐
    - `plainAnswer`: 텍스트로 정리한 답변 (3안 요약, 수정 결과 등)
    - `html`: 리포트 HTML 코드. 리포트가 없는 단계에서는 빈 값
    - `session_id`: 세션 ID. 첫 요청에서 서버가 만들어 여기에 담음
  - `contexts`: 이번 요청에서 에이전트가 호출한 **도구의 결과** 목록 (RAG 문서 아님)
  - `trace`: 에이전트가 거친 단계 기록
- Streamlit 검증 UI는 `answer.html` 값을 받아 리포트를 화면에 표시합니다.
- 다단계 흐름(입력 → 3안 → 선택 → 대화 수정 → 리포트)은 모두 같은 `/query`로 처리하며, 단계는 `session_id`로 이어집니다. 별도 엔드포인트는 없습니다.
- 세션 상태(선택한 안, 대화 이력)는 서버 메모리에 둡니다. DB는 쓰지 않습니다 (v1 범위).

### 설정 (환경변수, 서버 측)
| 변수 | 값 |
|---|---|
| `AWS_DEFAULT_REGION` | `us-east-1` |
| `BEDROCK_MODEL_ID` | `us.anthropic.claude-sonnet-4-5-20250929-v1:0` |

- API 키·자격 증명은 서버 환경변수로만 설정하며, 사용자 화면에서 입력받지 않습니다.

### 상태 관리
- 선택한 안, 대화 수정 이력은 Streamlit 세션 상태에 두고, 같은 탭이 열려 있는 동안만 유지합니다.
- 영구 저장소(DB, 파일)는 두지 않습니다.

## 8. 산출물 (고정 구조)

제출 규약의 폴더 구조를 그대로 따릅니다. 파일을 추가로 만들지 않습니다.

- `src/agent.py` — 메인 에이전트 그래프 (LangGraph, `create_agent`)
- `src/tools.py` — 도메인 도구 (합계, 예산 판정, 재조정)
- `src/api.py` — FastAPI 앱, `POST /query` 노출
- `src/config.py` — `.env` 읽기 (새 파일, 사용자 허가)
- `src/ui.py` — Streamlit 검증 UI (`POST /query` 호출, `answer.html` 표시)
- `src/retriever.py` — **만들지 않음** (RAG 미구현)
- `data/` — **mock 데이터를 둠**. 실제 외부 데이터 대신 쓰는 샘플 자료이며, 외부 조회는 여전히 하지 않음 (내용은 아래 9절 참고)
- `evaluation/test_queries.csv` — AC1~AC6 전부를 CSV로 옮김. 평가 리포트도 여기에 둠
- `tests/` — 자동 테스트(AC1~AC5). 고정 구조에는 없지만 사용자가 추가를 승인함
