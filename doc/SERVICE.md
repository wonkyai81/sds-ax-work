## 1. 목적

사용자가 **여행지, 여행 기간, 인원, 예산(원화, 선택)** 을 입력하면, AI 에이전트가 예산에 맞는 여행 일정 후보 3개를 만들어 주고, 사용자가 그중 하나를 고르고 대화로 고쳐 나가며, 최종적으로 선택한 일정의 **HTML 리포트** 를 화면에서 확인하는 웹앱입니다. 출발지와 여행 날짜는 선택 입력입니다.

## 2. 범위

### 포함 (v1)
- 여행지·기간·인원 입력 (필수). 예산·출발지·날짜는 선택 (제한 없음: 기간, 예산, 국내·해외 모두 허용)
- 일정 후보 3안 생성 (맛집형, 명소형, 가성비형). 안마다 예산 대비·차별점·주요 일정을 카드로 요약
- 사용자 선택 (HITL: Human-in-the-loop)
- 선택한 안에 대한 대화형 수정
- 예산 초과 시 AI 자동 재조정
- 선택한 안의 HTML 리포트 화면 표시 (일정표, 맛집·명소 가이드북, 준비물·유의 사항 3탭)와 HTML 파일 내보내기 (브라우저 내려받기)
- 외부 데이터 조회 (선택 사항, `MOCKDATA_USE=False` 일 때만): 장소·평점·해외 경로(Google Maps MCP), 항공·입장권·숙소 가격(마이리얼트립 MCP), 국내 경로(네이버), 환율(Frankfurter), 5일 날씨(OpenWeatherMap), 명소 대표 이미지(위키백과). 연결이나 키가 없으면 해당 조회만 건너뛰고 LLM 추정으로 진행

### 제외 (v1)
- 예약·결제 연동, 조회값의 실시간 보장 (조회 결과도 참고용 추정값으로 표시)
- 로그인, 계정
- 서버 측 일정·리포트 저장, 공유 (리포트 HTML 내려받기만 허용)
- 새로고침 후 상태 복원 (선택한 안과 대화 이력은 같은 탭이 열려 있는 동안만 유지)
- 환율 설정 화면 (환율은 조회해 사용하고, 조회에 실패하면 원화로 직접 추정)
- RAG 파이프라인 (문서 검색, 임베딩, 벡터 저장소). 답변 근거는 도구 호출 결과로만 제공

## 3. 사용자 흐름

1. **입력**: 여행지, 기간, 인원(필수). 예산(원), 출발지(없으면 서울), 날짜(없으면 오늘+30일)는 선택
   - 필수 항목이 빠지면 무엇이 빠졌는지 되묻고 같은 세션으로 이어서 받음
2. **3안 생성**: 맛집형 / 명소형 / 가성비형 각각 일차·시간대별 일정과 항목별 비용(원) 제시. 안마다 예산 대비, 다른 안과의 차별점, 주요 일정(최대 5개)을 함께 보여줌
   - 응답 지연이나 호출 한도 오류는 자동으로 다시 시도(최대 3회)하고, 끝내 만들지 못한 안은 빼고 나머지 안으로 진행하며 제외된 안을 안내함
3. **예산 검사**: 코드가 합계를 계산하고 예산 충족 여부를 판정 (아래 4절). 예산이 없으면 판정과 재조정을 하지 않음
4. **안 선택**: 사용자가 한 안을 고름. 안을 고르기 전에는 수정 요청을 받지 않음
5. **리포트와 가이드**: 선택한 안의 경로 정보를 채우고, 맛집·명소 가이드북과 준비물·유의 사항을 만들어 리포트에 담음
6. **대화 수정**: 예) "2일차 저녁을 고급 스시 오마카세로 바꿔줘"
   - 수정 후 합계가 예산을 넘으면 자동 재조정 실행
   - 수정 결과로 리포트를 다시 표시. `종료`를 입력하면 세션을 끝냄

## 4. 예산 규칙

| 안 | 예산 기준 |
|---|---|
| 맛집형 | 합계 ≤ 사용자 예산 |
| 명소형 | 합계 ≤ 사용자 예산 |
| 가성비형 | 합계 ≤ 사용자 예산의 80% |

- **판정 주체**: 코드. LLM은 항목별 단가를 추정하고(조회한 값이 있으면 그 값을 우선), 인원·객실·박 수 곱셈, 환율 환산, 합계, 충족 여부는 코드가 계산합니다. 화면에 보이는 합계와 예산 대비 비율은 모두 이 계산값입니다.
- **식사 가격**: 조회한 가격대를 아는 식당의 1인 가격은 가격대별 고정 기준으로 정합니다. 저렴 1만원, 보통 2만원, 비쌈 5만원, 매우 비쌈 10만원이며 국가와 무관합니다. 가격대를 모르는 식당은 추정합니다.
- **항공·숙소 가격**: 마이리얼트립에서 항공·숙소를 조회했으면 해당 항목의 금액을 LLM이 쓴 값 대신 조회값으로 코드가 정합니다.
  - 항공: 1인 왕복 요금을 쓰고, 가는 편과 귀국 항목의 시각·편명·날짜도 같은 항공권 기준으로 맞춥니다. 가성비형은 최저가, 맛집형·명소형은 직항 중 최저가(직항이 없으면 최저가)를 고릅니다. 항목에 조회된 항공사 이름이 적혀 있으면 그 항공사를 우선합니다.
  - 숙소: 일정의 숙소 이름이 조회한 숙소 이름과 맞으면 그 1박 객실 요금을 씁니다. 이름이 맞지 않으면(사용자가 직접 고른 숙소 등) LLM이 쓴 값을 그대로 둡니다.
  - 입장권·투어는 항목과 상품 이름을 짝짓기 어려워 지금처럼 조회 가격을 참고해 LLM이 씁니다.
- **최소 단가**: 식사와 숙박은 0원으로 둘 수 없습니다. 추정값이 최소 단가보다 낮으면 식사 1인 3천원, 객실 1박 3만원으로 올려 계산하고 비고에 표시합니다. 예산에 맞추려고 비용을 비현실적으로 낮춰 "예산 충족"이 되는 일을 막기 위해서입니다.
- **예산 없음**: 예산은 선택입니다. 없으면 금액 제한 없이 3안을 만들고, 재조정과 초과 경고를 하지 않습니다.
- **통화**: 모든 금액과 판정은 원화(KRW). 해외 여행지는 현지 통화로 추정한 단가를 조회한 환율로 원화로 바꿔 계산하고, 환율 조회에 실패하면 원화로 바로 추정합니다. 합계는 항상 원화 금액의 합입니다.
- **인원 비용**: 입장권·식당 식사·항공권은 `1인 가격 x 인원` 으로 전체 비용을 계산합니다. 숙박은 `객실 1박 요금 x 객실 수(2명당 1실, 홀수는 올림) x 박 수` 의 총액이며, 1일 여행에는 숙박이 없습니다.
- **차별점 문장**: 3안 카드의 차별점은 2~3문장(250자 이내)이며 금액·합계·비율 숫자를 쓰지 않습니다. 숫자는 계산값만 보여줍니다.

### 자동 재조정
- 예산을 못 맞춘 안마다 **안별로 최대 3회** 재조정합니다.
- 3회 후에도 못 맞추면 **가장 근접한 안**을 보여줍니다. 가장 근접한 안은 "목표 예산 대비 초과 금액이 가장 작은 시도"입니다.
- 가장 근접한 안에는 초과 경고를 함께 표시합니다.
- 대화 수정으로 선택한 안의 합계가 예산을 넘으면 같은 재조정 규칙(최대 3회, 가장 근접한 안)을 다시 적용합니다.
- 3안 제시 기능(HITL 선택)과 예산 초과 재조정은 **서로 독립된 기능**입니다.

## 5. 리포트 구성

선택한 안의 HTML 리포트에 아래 항목이 포함되어야 합니다.

- 일차·시간대별 일정 (출발·도착 시각 HH:MM, 출발지·도착지, 소요시간 포함)
- 항목별 활동, 비용(원), 교통수단, 비고 (비용 근거 또는 특이 사항). 1인 단위 항목은 `1인 가격 x 인원 = 전체 가격` 으로 표시
- 항목별 비용 합계
- 예산 대비 잔액 (예산 − 합계, 초과 시 음수)
- 초과 경고 (합계가 목표 예산을 넘을 때)

리포트는 탭 3개입니다.
1. **일정표**: 위 항목, 출발지·조회 기준 날짜·인원 표시, 예산 진행 막대, 참고 가격과 환율 카드
2. **맛집 및 명소 가이드북**: 맛집 4곳·명소 4곳. 명소 카드에는 대표 이미지(없으면 기본 이미지)
3. **준비물·유의 사항**: 날씨 요약, 준비물, 목적지 사전 유의 정보, 여행 중 유의 사항

표시 방식: **화면에 표시**. 서버에는 저장하지 않으며, 사용자가 "HTML로 내보내기" 로 현재 리포트를 단독 HTML 파일로 내려받을 수 있습니다.

### 역할 분담
- **에이전트 (LangGraph, `src/agent.py`)**: 일정 생성, 재조정 흐름, 대화 수정 흐름을 그래프로 구성
- **도구 (`src/tools.py`)**: 합계 계산, 예산 판정, 재조정 시도 횟수 관리 등 결정적 로직. 판정은 LLM이 아니라 도구(코드)가 수행
- **API**: FastAPI, 제출 규약의 `POST /query` 가 기본 계약. 같은 처리를 NDJSON으로 진행 상태와 함께 보내는 `POST /query/stream` 과 웹 UI를 돌려주는 `GET /` 를 더함 (아래 6.1)
- **웹 UI (`web/index.html`)**: 입력, 3안 카드 선택, 대화 입력, 진행 표시, 리포트 표시와 내보내기를 담당. 에이전트 로직은 두지 않음
- **Streamlit**: 입력, 안 선택, 대화 입력, 결과 표시만 담당. 에이전트 로직은 두지 않음. 검증용 UI이며 `POST /query`를 호출해 동작
- **가드레일 (`src/tools.py`, `src/api.py`)**: 비밀 값·개인정보·실시간 조회 요청과 필수 항목 누락을 에이전트 호출 전에 규칙으로 거름

### 6.1 API 계약 (제출 규약)
- 요청: `POST /query`, 본문 필드
  - `question`: 사용자의 **자연어 요청 한 줄**
  - `session_id`: 첫 요청에서는 생략. 서버가 새 세션을 만들어 응답에 돌려주고, 이후 요청에는 이 값을 함께 보냄
- 같은 본문을 `POST /query/stream` 에도 보낼 수 있습니다. 진행 상태를 함께 받는 NDJSON 응답이며, 웹 UI의 진행 표시용입니다.
- 응답: `answer`, `contexts`, `trace` 세 키
  - `answer`: JSON 구조. 아래 두 키를 가짐
    - `plainAnswer`: 텍스트로 정리한 답변 (3안 요약, 수정 결과 등)
    - `html`: 리포트 HTML 코드. 리포트가 없는 단계에서는 빈 값
    - `session_id`: 세션 ID. 첫 요청에서 서버가 만들어 여기에 담음
  - `contexts`: 이번 요청에서 에이전트가 호출한 **도구의 결과** 목록 (RAG 문서 아님)
  - `trace`: 에이전트가 거친 단계 기록
- 3안 선택 단계의 `plainAnswer` 에는 안마다 예산 대비, 차별점, 주요 일정이 담기고, 웹 UI는 이를 카드로 보여줍니다. 응답 키는 늘리지 않습니다.
- 웹 UI와 Streamlit 검증 UI는 `answer.html` 값을 받아 리포트를 화면에 표시합니다.
- 다단계 흐름(입력 → 3안 → 선택 → 대화 수정 → 리포트)은 모두 같은 `/query`로 처리하며, 단계는 `session_id`로 이어집니다.
- 오류는 `{"error": {"code", "message"}}` 이고 HTTP 422(입력·가드레일 거절), 404(세션 없음·종료), 500(그 밖)입니다. 필수 항목 누락 오류에는 `session_id` 와 `missing` 이 함께 옵니다.
- 세션 상태(선택한 안, 대화 이력)는 서버 메모리에 둡니다. DB는 쓰지 않습니다 (v1 범위).

### 상태 관리
- 선택한 안, 대화 수정 이력은 서버 메모리에 `session_id` 단위로 두고, 브라우저는 `session_id` 만 같은 탭이 열려 있는 동안 들고 있습니다.
- 서버를 다시 시작하면 세션이 사라집니다. 영구 저장소(DB, 파일)는 두지 않습니다.

| AC5 | Bedrock 리전·모델 ID를 환경변수에서 읽고, 사용자 API 키 입력이 없다 |
| AC6 | 여러 대표 입력(예: 도쿄, 3박 4일, 2명, 100만원)으로 입력 → 3안 → 선택 → 대화 수정 → 리포트 화면 흐름이 실제 Bedrock으로 동작하고, 같은 탭에서 선택·대화 이력이 유지된다 |

- 자동 테스트는 모두 네트워크 없이 Bedrock과 외부 연동을 모킹해 실행합니다. 현재 157개가 통과합니다 (`python -m pytest tests -q`).
- 가드레일, 세션 재개, 안 선택 인식, 선택 전 수정 거절, 웹 UI 정적 검사는 `tests/test_api.py` 에서, 외부 조회 연결(MCP·환율·날씨·경로)과 3안 카드 정보는 `tests/test_plans.py`, `tests/test_budget.py` 에서 확인합니다.
