## Goal

사용자가 여행 조건을 입력하면 테마가 서로 다른 3개의 일정안을 생성한다. 사용자는 그중 하나를 선택하고 대화로 수정한 뒤, 일자별 일정과 합계가 담긴 리포트를 받는다(MVP 흐름: 입력 → 3안 → 선택 → 대화 수정 → 리포트, doc/SERVICE.md 정의 기준).

## User Stories

1. **As a** 여행 계획자 (doc/SERVICE.md에 정의된 핵심 사용자), **I want to** 목적지·일수·인원은 꼭, 예산·출발지·날짜·필수 장소 등은 원하면 제한 없이 입력한다(국내·해외 모두 가능), **so that** 자신의 조건에 맞는 일정 초안을 빠르게 받을 수 있다.
2. **As a** 여행 계획자, **I want to** 관광·휴식·미식 등 테마가 서로 다른 3개의 일정안을 비교한 뒤 하나를 선택한다, **so that** 성격이 다른 대안 중에서 자신의 취향에 맞는 일정을 고를 수 있다.
3. **As a** 여행 계획자, **I want to** 선택한 일정을 대화로 수정한다(예: 둘째 날 오후를 쇼핑으로 변경), **so that** 나머지 일정은 그대로 두고 원하는 날만 바꿀 수 있다.
4. **As a** 여행 계획자, **I want to** 일자별 일정과 합계가 담긴 리포트를 확인하고 필요하면 HTML 파일로 내려받는다(일정표, 맛집·명소 가이드북, 준비물·유의 사항), **so that** 최종 여행 계획과 총비용을 한눈에 파악하고 가져갈 수 있다.
5. **As a** 예산이 부족한 여행 계획자, **I want to** 예산 안에서 실현할 수 없는 조건으로 일정을 요청한다, **so that** 가장 근접한 일정과 함께 초과 금액과 경고를 보고 현실적인 판단을 내릴 수 있다.

## Constraints

- 로그인 없이 사용한다.
- 일정은 한 세션(같은 탭) 안에서만 유지한다. 새로고침이나 재방문 시 유지는 요구하지 않는다.
- 지원 기기는 데스크톱 브라우저로 한정한다. 모바일 화면은 V1 범위 밖이다.
- V1의 장소·영업시간·입장료·숙박·교통 가격은 기본적으로 AI 추정값(mock)을 사용한다. 외부 연결(`MOCKDATA_USE=False`)을 켠 경우에만 장소·가격·경로·환율·날씨 조회값을 참고하며, 조회에 실패하면 AI 추정값으로 대체한다. 조회값도 참고용이다.
- V1 입력 범위에는 제한을 두지 않는다. 일수, 인원, 예산, 국내·해외 목적지를 모두 허용한다. 필수 입력은 여행지·일수·인원이고 예산·출발지·날짜는 선택이다.
- 화면 언어는 한국어만 지원한다.
- 3안 생성 시간과 수정 반영 시간에는 상한을 두지 않는다.
- V1에서는 예약 연동, 서버 측 일정 저장·공유, 지도 표시를 제외한다. 리포트를 HTML 파일로 내려받는 기능만 허용한다.
- 일정·가격 정보가 AI 추정값이라는 안내 문구를 화면에 표시한다.
- MVP 흐름은 입력 → 3안 → 선택 → 대화 수정 → 리포트이다(doc/SERVICE.md 정의대로).

## Success Criteria

1. evaluation/test_queries.csv의 평가 시나리오 12건이 모두 통과한다(12/12). 각 시나리오는 1회 실행해 통과하면 합격으로 본다. (현재 자동 채점은 1회차 12/12, 5회차 12/12이며, 두 회차 모두 외부 정보 연결을 켠 상태(`MOCKDATA_USE=False`)로 실행했다. 평가는 이 조건을 기준으로 한다.)
2. 한 시나리오가 통과하려면 자동 점검과 PM 체크리스트(사람 확인)를 모두 충족해야 한다.
3. 자동 점검: 요청한 일수를 지킨다. 필수 장소를 모두 포함한다. 예산을 준수하거나, 예산이 부족한 경우 초과 표시 규칙을 충족한다.
4. PM 체크리스트(검토자: PM 본인), 항목 중 하나라도 어기면 불합격: (1) 하루 안에서 같은 지역을 불필요하게 오가지 않는다. (2) 식사 시간대에 식사 일정이 들어 있다. (3) 장소 이름이 해당 도시에 실제로 있는 곳으로 보인다.
5. 하루 이동시간 합과 하루 방문지 수에는 상한을 두지 않으며, 판정 기준에 포함하지 않는다.
6. 3안의 테마(예: 관광·휴식·미식)가 3개 모두 서로 다르다.
7. 예산이 부족한 요청은 다음 세 조건을 모두 충족해야 통과한다: (a) 테마가 다른 3안이 그대로 나온다. (b) 각 안에 총예상 비용, 초과 금액, 경고 문구가 표시된다. (c) 일수와 필수 장소를 줄이지 않고 지킨다.
8. 대화 수정 시 요청한 날만 바뀌고 나머지 날의 일정과 필수 장소는 유지된다.
9. 리포트에 일자별 일정과 합계가 포함된다.
10. 화면에 일정·가격 정보가 AI 추정값이라는 안내 문구가 표시된다.
11. 로그인 없이 사용할 수 있고, 같은 탭 안에서는 생성한 일정이 유지된다.
12. 예약 연동, 서버 측 저장·공유, 지도 표시 기능이 V1에 포함되지 않는다. 가격·영업시간 조회는 선택 연결이며 결과는 참고용으로만 표시한다.

> 참고: 기준 8의 대화 수정 동작은 `tests/test_chat_edit.py` 자동 테스트로 검증하고, 평가 문항 TQ-05(수정 반영, 합계·판정 재계산)에서도 확인한다.
> 자동 점검은 현재 방식으로 수행한다. `evaluation/run_eval.py` 가 기대 도구 호출과 금지 항목만 자동 채점하고, 일수·필수 장소·테마 차이는 사람이 확인한다.

## Assumptions

- 핵심 사용자 정의는 인터뷰에서 명시되지 않았으며, doc/SERVICE.md의 정의를 따른다고 가정한다.
- '정해진 제약 없음'이라는 초기 답변은 이후 확정된 운영 제약(로그인 없음, 세션 유지, 데스크톱 전용, 기능 제외 목록)으로 보완된 것으로 본다. 완성 기한, LLM·외부 API 사용 여부, 월 비용 상한은 정해지지 않았다.
- mock 데이터(AI 추정값)를 사용하므로, 체크리스트 항목 '실제로 있는 곳으로 보인다'는 PM의 주관적 판단으로 확인한다고 가정한다.
- 예산이 충분한 시나리오의 '예산 준수'는 각 안의 총예상 비용이 입력 예산 이하인 것으로 해석한다.
- 출시 이후의 성과 지표(사용자 만족도, 이용률 등)는 인터뷰에서 다뤄지지 않았으며, 계약 조건이 아닌 PM의 후속 과제로 본다.
